# QR起点・現在登録所有者確認の仕様

状態: 2026-09-25の合意を反映した仕様。Curvegrid向けAPI・コントラクト・CLIは実装済み。実環境の受け入れ試験とスマホ結合は未実施。相談用のUIモックは別途 [UI_MOCK_PLAN.md](UI_MOCK_PLAN.md) に記録する。

カメラは `UI_CAMERA_MODE=mock|live` で切り替える。実スキャンと端末内写真読取りの受付条件・停止条件・検証範囲は [カメラ仕様](CAMERA_SCAN.md) を参照。既定のモック動作を維持する。

## 目的と対象

2026-09-26 JSTに、実接続前の [Web API詳細設計](BACKEND_DESIGN.md) と [OpenAPI定義](openapi.yaml) を追加した。MultiBaas・署名・送信を固定モックにする設計であり、以下の実接続要件を満たした実装とは扱わない。固定モックAPIの実装と試験は [BACKEND_IMPLEMENTATION.md](BACKEND_IMPLEMENTATION.md) に記録する。追加したCurvegrid連携の範囲と未達条件は [CURVEGRID_INTEGRATION_IMPLEMENTATION.md](CURVEGRID_INTEGRATION_IMPLEMENTATION.md) を参照。

天地愛プロジェクトの「証明くん」は、個人が自分の記録を登録し、必要な相手へ証明情報を提示する「証明の民主化」を目指す既存プロジェクトである。個人向けPoCがハッカソン以前から存在する。

今回は、物理カードのQRコードから現在の登録所有者を確認する追加機能の参照実装とデモを、このリポジトリで開発する。既存PoCから独立して動作させ、既存サービスの作り直しやデータ連携は行わない。

記録先はPolygon Amoyとする。アプリと発行者CLIはMultiBaas APIを中心に、状態の読取り、未署名取引の作成、レシート・イベントの取得を行う。登録者はMetaMaskで取引を署名・送信する。MultiBaasの応答やローカル保存値をチェーン上の記録の代わりにはしない。

架空の野球選手「証明一郎」のカード右下にカード固有のQRを配置する。任意のウォレットの利用者が、スマートフォンからニックネームと所有者を登録する。実演用ニックネームは「おじいちゃんコンビニ」とする。第三者は同じQRを読み、ウォレットを接続せずに登録情報を閲覧する。

## 証明範囲

確認する事実は「発行者が発行したカードIDに対し、接続したウォレット本人の取引で所有者とニックネームが登録されたこと」である。

- 「現在の登録所有者」はシステム上の登録先を意味する。今回は一度限りの登録で、所有権移転、登録取消し、上書きは提供しない。
- QRをコピーしても同じ登録情報が表示される。物理カードの真贋、現物の所持、物理的な譲渡は判定しない。
- ニックネームは公開用の名札であり、実名確認や世界で唯一の名前を意味しない。
- ウォレット操作で確認するのはそのウォレットを操作できることまでである。

## 既存機能との境界

写真・動画の登録、アルバム管理、公開範囲の選択、共有URLによる提示、外部証跡の考え方は既存成果として扱う。今回の新規成果に数えない。既存利用者、保存データ、公開設定、証明記録を削除・初期化・変更・無断公開しない。

今回追加する範囲は、カード識別、発行者による登録許可、QRからの確認画面、本人ウォレットによる登録、カードと登録所有者の対応記録、第三者による読取りである。参照元と流用状況は [既存成果](PRE_EXISTING_WORK.md) に記録する。

## 役割と権限

| 役割 | 行えること | 制約 |
| --- | --- | --- |
| 発行者 | CLIによるカードIDの発行 | デモでは登録許可を全員に開放する。発行は所有者登録ではない。登録後の上書きや利用者の秘密鍵取得は行えない |
| 登録者 | 自分のウォレットでニックネームと所有者を登録 | アドレスの貼付けだけでは登録できない。登録後の変更・削除は提供しない |
| 第三者 | QRからカード、現在の登録所有者、根拠の取引情報を閲覧 | 閲覧だけでは登録・変更を行わない。閲覧にウォレットやMultiBaasへのログインを求めない |

## 機能要件

| ID | 機能 | 必須の動作 |
| --- | --- | --- |
| F01 | カード識別 | 発行者が登録した固有IDを使用する。同じ発行単位で重複を拒否する。未発行IDを自動作成しない |
| F02 | QR表示・読取 | 公開確認ページへ移動する。QRには秘密鍵、登録許可用の秘密情報、個人情報を含めない |
| F03 | 発行者の登録許可 | 正規発行者だけがカードIDを発行できる。デモは全員登録可能とする。発行と所有者登録を区別する |
| F04 | ウォレット接続 | 実際の接続アドレスとチェーンを確認する。アドレス手入力だけで本人の操作と扱わない |
| F05 | 登録 | 接続したウォレット本人の取引だけを受理する。二重登録、上書きをコントラクトで拒否する |
| F06 | ニックネーム | 文字列を所有者と同じ取引でオンチェーン記録する。登録後の変更・削除を提供しない。異なるカードで同名を許容する |
| F07 | 公開確認 | ウォレット未接続で閲覧できる。再読込や別端末でもチェーン上の記録を取得する |
| F08 | 外部証跡 | チェーン名・ID、コントラクトアドレス、カードID、発行者、登録取引ハッシュを確認できる。アプリを介さないRPC照合手順を提供する |
| F09 | 状態・エラー | 未発行、未登録、登録処理中、確認済み、失敗、確認不能を区別する。通信失敗を未登録や確認済みに置き換えない |
| F10 | 審査資料 | 仕様、採用計画、プロンプト、実際の実装と試験結果、変更履歴、人間の貢献、AI利用範囲を追跡可能にする |

F08ではAmoy Polygonscanの取引・コントラクトページへの導線と、Amoyの公開RPCを使った照合手順を用意する。第三者はアプリやMultiBaasを介さず記録を照合できる。未登録カードには登録取引がないため、その旨を表示する。エクスプローラーの障害だけで登録状態を変更しない。

## 画面と表示

対象はスマートフォンの縦画面のみとする。画面はQRスキャンを加えた次の4種類にまとめる。カード確認と公開確認は同一ページの状態違いとして扱う。発行者用のWeb画面は作らない。

| 画面 | 表示と操作 |
| --- | --- |
| QRスキャン | 「QRコードをスキャン」を押してからカメラ画面に進む。今回のUIモックでは遷移だけを模擬し、サンプルの読取りボタンでカード確認へ進む。実カメラ読取りは後続実装とし、端末カメラから公開URLを直接開く経路も保持する |
| カード確認・公開確認 | 「証明一郎」、カード画像、カードID、登録状態。発行済みかつ未登録のときだけ登録導線を表示する。登録済みなら「現在の登録所有者」、ニックネーム、ウォレット、発行者、チェーン、根拠の取引情報、照合手順への導線を表示する |
| 所有者登録 | ニックネーム入力、接続ウォレット・チェーン、公開情報の説明、登録内容の確認。氏名・メール欄は設けない。所有者アドレスの手入力欄は設けない |
| 登録処理 | ウォレット承認待ち、送信済み、記録確認中、成功、承認拒否・失敗、確認不能を区別する。連打を防ぎ、成功後に公開確認へ案内する |

スマートフォンの通常ブラウザからMetaMaskアプリへ接続して登録する。第三者の閲覧にはMetaMaskを必要としない。接続方法と実演手順は [デモ手順](DEMO.md) に記載する。

登録前に、ニックネームとウォレットが公開されること、登録後の変更・削除を提供しないことを説明する。カード確認画面では、このQRが現物の所持や真贋を判定しないことが分かる説明を添える。

### 言語

- 日本語と英語に切り替えられる。利用者の選択を保存し、再訪時も優先する。
- 選択がなければブラウザの言語優先順に対応言語を照合する。`ja-JP` などの日本語は `ja`、`en-US` などの英語は `en` として扱う。
- 最初に一致する `ja` または `en` を選び、一致しなければ英語とする。例えば `fr, ja, en` は日本語、`en, ja` は英語になる。
- 画面の説明、状態、エラー、確認文を翻訳する。ニックネーム、カードID、ウォレット、取引ハッシュなどの記録値は翻訳しない。

### 状態

未発行はカードが存在しないとチェーンから確認できた状態、未登録は発行済みで所有者登録がないと確認できた状態とする。取得中と取得失敗はそれぞれ独立して表示する。

登録処理中は、その端末が追跡している取引の状態である。他端末にも同じ処理状況が分かるとはみなさない。成功した取引レシートと登録内容の照合が完了してから確認済みにする。取引ハッシュが発行されただけでは成功にしない。

送信後に確認できなくなった場合は、取引ハッシュを使った再確認を案内する。再読込やアプリ復帰後にチェーンを照会し、自動的に再送しない。

## MetaMask接続準備の追加条件（2026-09-26）

接続前に使用ネットワークと準備の導線を表示する。未追加とは断定せず、ウォレットの未対応チェーン応答で追加を案内する。接続・追加・切替と登録取引を別の状態として扱う。MetaMaskへの移動中は次の承認要求を開始せず、ブラウザ復帰時に接続を再確認し、必要な操作を案内する。準備時には登録APIや署名を呼ばない。

前面で60秒応答を確認できない場合は再確認と手動案内を表示し、要求を自動再送しない。対象チェーンとアドレスが確認できたときだけ登録確認へ進める。モックの準備シナリオと閲覧専用モードを維持する。詳細と実機検証の区別は [接続準備計画](METAMASK_PREPARATION_PLAN.md) を参照。
